通过**反向采访**帮助用户理解一个功能的实现方案——AI 是被采访者（回答），用户是采访者（选问题）。

## 核心理念

理解一个实现方案最好的方式不是读一篇长文档，而是**带着问题逐层深入**。用户关心的维度不同（有人关心架构决策，有人关心数据流，有人关心边界处理），所以由用户选择想深入的方向。

> "最好的技术文档不是告诉你所有事情，而是回答你当前最想知道的事情。"

## 适用场景

- 刚完成一个功能实现，向用户（或自己）讲解方案
- 用户看到了代码变更，想理解设计思路
- 代码 review 前的方案讲解
- 新成员 onboarding，理解某个模块的实现

## 采访方法论

### 第 0 轮：确定采访主题

确认要讲解的功能/模块。如果用户没有明确指定，从对话上下文或最近的代码变更中推断。

操作：
- 明确功能名称和范围
- 使用 `Task`（Explore）或 `Grep`/`Read` 快速扫描相关代码，建立全局视图
- 准备一份**一句话概述** + **涉及的文件清单**

### 第 1 轮：全局概览（30 秒版本）

先给用户一个极简的全局概览——**如果只能用 3-5 句话讲完这个功能，你会怎么说？**

输出格式：
```
## {功能名} 概览

{3-5 句话概述：做了什么、为什么这么做、核心架构决策}

涉及文件：
- {文件1} — {一句话说明}
- {文件2} — {一句话说明}
- ...
```

然后用 `AskUserQuestion` 提供深入方向供用户选择。

### 第 2-N 轮：用户选题，AI 深入讲解

每轮：
1. **AI 回答**上一轮用户选择的问题，讲解对应的实现细节
2. **AI 提出**下一批问题选项，基于当前讲到的内容自然延伸

讲解原则：
- **先讲 Why，再讲 What，最后讲 How**——为什么这样设计 → 做了什么 → 具体怎么实现
- **用代码佐证**——关键逻辑引用具体文件和行号（`file.ts:42`），但不贴大段代码
- **对比替代方案**——如果有其他实现方式，简要说明为什么选了当前方案
- **标注取舍**——每个设计决策都有 trade-off，主动说明

### 问题生成策略

每轮生成 2-4 个问题选项，覆盖不同维度：

**架构维度**：
- "这个功能的整体数据流是怎样的？"
- "为什么选择 X 架构而不是 Y？"
- "各模块之间怎么协作？"

**数据维度**：
- "数据库 schema 是怎么设计的？"
- "新旧数据怎么兼容？"
- "数据一致性怎么保证？"

**执行维度**：
- "并发/异步是怎么处理的？"
- "错误处理和容错机制是什么？"
- "取消/中断的机制是什么？"

**UI 维度**：
- "用户看到的交互流程是什么？"
- "不同状态下 UI 怎么变化？"
- "前后端数据怎么同步？"

**边界维度**：
- "边界情况和异常路径怎么处理？"
- "向后兼容是怎么做的？"
- "性能瓶颈在哪里？"

**测试维度**：
- "怎么验证这个功能是正确的？"
- "有哪些测试覆盖？"

技巧：
- 问题选项要**具体到当前功能**，不要泛泛地问"架构是什么"
- 基于上一轮讲到的内容**自然延伸**——比如讲完数据库 schema 后，下一轮可以提"数据聚合是怎么算的"
- 始终保留一个"我想了解其他方面"的开放选项
- 当所有核心维度都覆盖后，提供"总结"选项结束采访

### 结束条件

当以下任一条件满足时，主动提供"总结回顾"选项：
- 核心维度（架构、数据、执行、UI）都已覆盖
- 用户选择了"总结"
- 已经进行了 5+ 轮问答

## 执行规则

1. **每轮必须用 `AskUserQuestion`**：提供问题选项让用户点选，这是采访的核心交互
2. **回答要有层次**：用标题/列表结构化，避免大段纯文本
3. **引用代码要精确**：给出文件路径 + 行号，让用户能直接跳转查看
4. **主动读代码验证**：回答前用 `Read` 确认细节，不要凭记忆回答
5. **控制单轮篇幅**：每个回答 200-400 字为宜，太长用户消化不了
6. **尊重用户节奏**：用户选什么就讲什么，不要强行按自己的顺序

## 总结格式

采访结束时，输出一份结构化的方案摘要：

```markdown
## {功能名} 实现方案摘要

### 一句话概述
{功能做了什么}

### 架构决策
- {决策1}：{原因}
- {决策2}：{原因}

### 数据模型
- {表/类型变更概要}

### 核心流程
1. {步骤1}
2. {步骤2}
3. ...

### 关键 Trade-off
- {取舍1}：选了 A 而非 B，因为 {原因}

### 涉及文件
| 文件 | 变更类型 | 说明 |
|------|---------|------|
| {file} | 新增/修改 | {一句话} |
```
