批量启动待办——列出 pending todo，用户选择后为每个创建独立工作区 + 需求澄清脚本。

## 流程

### 1. 列出 pending todo

读取 `.claude/skills/todo/pending/` 下所有 `.md` 文件，提取标题（`# ` 开头的第一行），带序号展示给用户：

```
1. 组件编译 console.error 触发 Next.js dev overlay
2. 清理 types.ts 中旧的 EvalRunRequest/EvalRunResponse
3. ...
```

### 2. 用户选择

用户通过序号指定要启动的待办，如 `1, 3, 5` 或 `1-4`。

如果用户在调用 skill 时已经附带了选择（如 `/batch-start 1,3,5`），跳过此步。

### 3. 批量创建工作区

对每个选中的待办，**并行**执行：

```bash
make wt-create NAME=<todo-filename-without-ext>
```

其中 `NAME` 取自 todo 文件名（去掉 `.md` 后缀）。

### 4. 生成 requirement-from-todo.sh

在每个工作区根目录创建 `requirement-from-todo.sh`，内容模板：

```bash
#!/usr/bin/env bash
# Auto-generated by todo-batch-start skill
cd "$(dirname "$0")"
claude --dangerously-skip-permissions "$(cat <<'PROMPT'
/requirement

{todo 文件的完整内容}
PROMPT
)"
```

然后 `chmod +x`。

### 5. 输出汇总

展示创建结果表格：

| # | 待办 | 工作区路径 | 分支 |
|---|------|-----------|------|
| 1 | ... | `.worktrees/xxx` | `dev-xxx-YYYYMMDD` |

并提示用户：
```
进入工作区运行需求定义：
  cd .worktrees/<name> && ./requirement-from-todo.sh
```

## 注意事项

- todo 文件名即工作区名，保持一致便于关联
- 脚本中 todo 内容用单引号 heredoc（`<<'PROMPT'`），避免 shell 展开
- 如果 `make wt-create` 失败（如同名工作区已存在），跳过并在汇总中标记失败原因
