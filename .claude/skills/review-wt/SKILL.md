对比工作区 `start.sh` 中的需求 prompt 与实际代码变更，输出结构化的 review 报告。

## 触发条件

当用户提到以下任意表述时调用：
- "review"、"review 一下"
- "检查改了什么"、"看看完成了没"
- "对比需求"、"需求覆盖了没"
- "帮我 review"

## 执行流程

### 第 1 步：提取需求

读取当前工作区根目录的 `start.sh`，从中提取 `claude --dangerously-skip-permissions` 后面的 prompt 字符串作为**原始需求**。

解析需求文档的结构：
- **功能描述**：列出所有功能点
- **验收标准**：逐条提取为 checklist
- **约束**：识别技术/业务约束
- **不做范围**：明确排除项

### 第 2 步：收集变更

按优先级依次收集三类变更，合并为完整的变更集：

1. **未暂存变更（Unstaged）**：
   ```bash
   git diff
   ```

2. **已暂存变更（Staged）**：
   ```bash
   git diff --cached
   ```

3. **上游分支提交记录（Committed）**：
   读取 `.worktree/meta.json` 中的 `baseBranch`，获取从 base 分支分叉后的所有提交：
   ```bash
   git log <baseBranch>..HEAD --oneline
   git diff <baseBranch>...HEAD
   ```

如果三类变更都为空，告知用户"当前工作区没有任何变更"并结束。

### 第 3 步：理解变更

对收集到的完整 diff 进行分析：

1. **变更文件清单**：列出所有改动的文件及变更类型（新增/修改/删除）
2. **变更摘要**：对每个文件用一句话概括做了什么
3. **关键逻辑变更**：识别核心代码逻辑（新 API、状态管理、UI 组件、hooks 等）
4. **测试覆盖**：是否有新增/修改测试文件
5. **文档变更**：是否更新了 `web/guide/` 下的文档

如果 diff 过大（超过 3000 行），使用 `Task`（subagent_type=Explore）分文件阅读理解，避免遗漏。

### 第 4 步：需求覆盖度分析

将需求文档中的每一条功能点和验收标准，逐条与变更内容对比：

对每条验收标准给出三种状态：
- ✅ **已实现**：代码变更中有明确的对应实现
- ⚠️ **部分实现**：有相关代码但可能不完整，说明缺失什么
- ❌ **未实现**：没有找到对应的代码变更

### 第 5 步：代码质量检查

基于 CLAUDE.md 中的项目约定，检查以下方面：

**UI 约定**：
- 是否使用了 `<Spinner />` 而非 `Loader2Icon`
- Dialog/Sheet 表单是否只有 Cancel + Primary Action（无 Reset）
- 表单 label 是否用了 `text-xs font-medium text-muted-foreground`
- 是否有未遵循的 UI 约定

**代码约定**：
- react-hook-form 是否用了非受控模式
- 是否有 `useState` 镜像表单值的反模式
- 是否有 `watch()` 全量订阅
- API 错误处理是否用了 `toast.error()`

**约束遵守**：
- 检查需求中的"不做"范围是否被意外改动
- 检查需求中的"约束"是否被违反

只报告实际存在的问题，不列举通过的检查项。没有问题则说"未发现约定违规"。

### 第 6 步：收尾检查项

检查项目收尾要求的完成情况：
- [ ] 是否有对应的测试用例（`__tests__/` 目录下）
- [ ] `web/guide/` 文档是否与代码变更一致
- [ ] `make typecheck` 是否通过（提示用户运行，不自动执行）
- [ ] `make test` 是否通过（提示用户运行，不自动执行）

## 输出格式

```markdown
# Review 报告

## 需求摘要
{一句话概括 start.sh 中的需求}

## 变更概览
| 文件 | 类型 | 摘要 |
|------|------|------|
| path/to/file | 新增/修改/删除 | 一句话描述 |

## 需求覆盖度

### 功能点
- ✅ {功能点 1}
- ⚠️ {功能点 2}——{缺失说明}
- ❌ {功能点 3}

### 验收标准
- ✅ {验收标准 1}
- ❌ {验收标准 2}

**覆盖率**：X/Y（Z%）

## 代码质量
{问题列表，或"未发现约定违规"}

## 收尾检查
- ✅ 测试用例：已新增 `xxx.test.tsx`
- ⚠️ 文档更新：`web/guide/sessions.md` 已修改但可能需要补充 XX 部分
- ⏳ typecheck：待运行
- ⏳ test：待运行

## 总评
{一段话总结：整体完成度、主要风险、建议的下一步行动}
```

## 注意事项

- **只做分析，不做修改**：本技能只输出 review 报告，不修改任何代码
- **客观准确**：每个判断都要有 diff 中的依据，不猜测
- **关注遗漏而非风格**：重点检查功能完整性，风格问题只在明确违反 CLAUDE.md 约定时才提
- **大 diff 处理**：超过 3000 行时分批处理，确保每个文件都被 review
